# 桌面 UIA 变化与限制

`list-windows` 返回可持久化描述所需的进程路径、窗口类和最小化状态。目标 JSON 在已有进程名、精确标题、UIA 元素身份与祖先路径之外可加入 `appPath` 和 `windowClass`，resolve 逐项筛选并报告缺失条件。最小化时不返回可能失效的矩形。路径或标题变化、同名多窗口及 UIA 树变化仍需要调用方处理；不支持模糊标题。

坐标保持 Windows UIA 的虚拟桌面绝对像素，覆盖层按 VirtualScreen 四边判断交集，不把负坐标当作错误；进程启动时尝试请求 PerMonitorV2，失败回退到系统 DPI 感知。没有提供进程 manifest，也没有证明混合 DPI 的行为。

覆盖层显式设置透明、分层和不激活样式，并在 resolve 返回最小化或离屏时隐藏。去掉每次轮询强制重绘以避免不必要的刷新；真实点击、焦点、窗口跟随与闪烁尚需按验收记录中的判据测试。

完整证据和未覆盖项见 `acceptance/desktop-uia-2026-11-14/RESULTS-gaps.md`。

本次修复将覆盖层 UI 线程设为 PerMonitorV2 并检查线程上下文，避免 PowerShell 宿主已初始化进程 DPI 后设置进程模式失败。验收采样线程也采用相同的物理坐标系。实测初始矩形吻合；30 步移动最大单轴偏移 70 像素，子进程轮询仍有延迟。真实点击验收仍未完成，详见验收记录。

停止移动后 500ms 的实际对照中覆盖层与目标偏移归零，支持移动时偏移属于跟随延迟；本机 SetForegroundWindow 未能将自建记事本置前，受保护的真实点击已放弃。

真实点击复测在输入线程附着后命中自建记事本并取得按钮焦点；点击后覆盖层隐藏，原因仍需调查，不能视为持续显示已验收。

点击同为 topmost 的目标可能让目标暂时遮住覆盖层。成功 resolve 后使用不激活的 SetWindowPos 重新置顶；本次点击实测约 700ms 仍被遮挡，约 1.8s 的采样时已恢复。原有 IsWindowVisible=false 的原因由于旧记录缺少进程及 resolve 证据仍未确定。
